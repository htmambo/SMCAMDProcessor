# AMDRyzenCPUPM 唤醒 P-state 恢复修复计划

**Status**: 🔄 In progress (start time: 2026-11-17)
**Created**: 2026-11-17
**Creator**: Kimi Code

## 1. 目标与背景

长睡眠唤醒后，Ryzen 9 5900HX 的 P1 定义仅丢失 bit63 启用位，P0/P2 仍启用；Power Tool 因遇到首个禁用项即停止扫描，只显示 P0。当前唤醒恢复不检查 MSR 写入结果、不读回验证，随后重新采样还会把未验证的硬件表覆盖到缓存。

本次修复目标：

- 唤醒后按睡前快照恢复 P-state，并校验启用位与频率字段。
- 恢复失败时有界重试，不用未验证的硬件表覆盖 last-known-good 快照。
- 将恢复放到 work loop，与定时采样串行执行。
- Power Tool 正确显示非连续启用档位，并保留真实 P-state 编号映射。
- 保持 UserClient ABI 不变，不处理独立的 90°C 热管理问题。

## 2. 已确认事实与边界

- 当前配置 `standby=0`、`hibernatemode=0`，本次不引入 standby/hibernate 专用路径。
- P-state 定义逐核写入继续使用现有 `mp_rendezvous`；work loop 负责串行调用。
- 受保护字段仅为 bit63、FID、DfsId。电压/IDD 等字段允许固件合法调整，不参与漂移判定。
- PStateCtl 是动态选择器，只检查写入结果，不要求读回值保持不变。
- 用户主动禁用的档位必须保持禁用；last-known-good 不是“全部启用”的固定模板。
- P3–P7 等无效项不写回；有效/无效布局也必须与快照一致。
- 不新增锁，不在全核屏障内调用 IOLog，不新增 panic，不自动部署或触发系统睡眠。

## 3. 实施任务

### T1 内核：可验证的 P-state 表读写 ✅

- 为 `dumpPstate()` 增加“只读、不更新缓存”的内部模式。
- 增加受保护字段比较及缓存提交辅助逻辑。
- 显式 `writePstate()` 改为检查逐核写入结果并读回验证；只有验证成功才更新缓存，失败向 UserClient 返回错误。
- 初始开机成功读取的表作为初始缓存；用户验证通过的表成为后续睡眠快照。

### T2 内核：唤醒恢复下沉与有界重试 ✅

- `setPowerState(1)` 只设置恢复状态、重建能量基线并恢复 work loop，不再在 PM 回调中直接执行 MSR 恢复。
- work loop 首次唤醒 tick 执行全核写回和立即验证，50 ms 后再验证一次，覆盖短暂的固件异步重置窗口。
- 最多恢复 5 次；失败后在屏障外记录明确日志，并保留 last-known-good 表。
- 唤醒后的初始化不再用未经校验的 `dumpPstate()` 覆盖恢复快照，也不再无条件把 `PStateCtl` 缓存清零。
- 再次睡眠时取消尚未完成的恢复/验证状态，避免跨周期残留；5 次预算在每次唤醒时独立重置。
- 延迟校验失败重新进入恢复并消耗同一次唤醒的预算；所有中间失败在屏障外输出调试日志，最终失败输出警告。
- 逐核写入结果在全核屏障内聚合；读回在 work loop 调用核执行，作为包级缓存视图校验，不宣称覆盖每核独立漂移。

### T3 App：非连续档位与实时刷新 ✅

- 遍历全部 8 项并筛选启用项，不再遇到首个禁用项就停止。
- 普通 `updatePStateDef()` 同时刷新 raw 定义和频率缓存。
- 保存启用项的真实 P-state 编号；手动选择时映射回原编号，避免压缩显示后把 P2 错写为 P1。

### T4 审查与构建 ✅

- 使用已配置的 External Review MCP 审查计划与代码，修复阻断问题。
- 运行 `./Scripts/build.sh --clean`，覆盖项目标准 Release 四 scheme 构建与打包。
- 检查最终 diff、生成文件和工作区状态，不提交 Git commit。

### T5 复核发现修复 ✅

针对 2026-11-17 未提交改动的复核结果，修复以下问题：

- 写入校验失败改返回 `kIOReturnIOError`，与权限失败 `kIOReturnNotPrivileged` 区分；App 不再把校验失败误报为“权限不足”。
- 读回校验只比较实际读成功的项；仅当全部读取失败时才判失败。缓存也只提交读成功的项，避免不可读的 PSTATEDEF MSR 导致每次唤醒误报恢复失败。
- `writePstate()` 仅在写入与校验都成功后清除 `pstateDumpPending` / `pstateDumpRetryExhausted`，失败的用户写入不再取消待执行的补 dump。
- `wakePstateSkipInitDump` 在 init 消费后复位，避免未来非唤醒重初始化静默跳过 P-State dump 与 `PStateCtl` 归零。
- 唤醒快照无有效项时直接跳过恢复，不再消耗 5 次重试并输出假失败警告。
- App：P-State 编辑器 `CpuDfsId` 掩码由 `0x1f` 修正为 `0x3f`（与内核一致）；有效档位为空时跳过频率图绘制，避免强制解包空数组。
- 未处理：唤醒重试窗口内再次睡眠时，`sleepState.pstate` 的 memcpy 与在执行的校验仍存在数据竞争；按“不新增锁”的约束保持现状，已在 §5 记录。

### T6 真机验收（由用户执行）⏳

- 部署配套的新 kext 与新 App 后，记录冷启动 P0/P1/P2 原始值。
- 分别执行短睡眠和长睡眠唤醒，确认启用位与频率字段和睡前一致。
- 验证用户主动禁用项唤醒后仍保持禁用。
- 检查恢复成功/失败日志；若失败，确认日志可见且不会静默采纳漂移表。
- 验证 Power Tool 在非连续启用表下显示 P0/P2，手动选择 P2 时写入真实索引 2。

## 4. 验收标准

- Release 构建和打包成功，无新增编译警告导致的失败。
- 睡前快照不会被未经校验的唤醒后采样覆盖。
- 写入失败、读回失败或受保护字段漂移均进入有界重试；最终失败有日志。
- 无屏障内日志、无新增锁、无 UserClient ABI 变化。
- App 对 P0 enabled / P1 disabled / P2 enabled 显示两个选项，并正确映射 P2。
- 写入后读回校验失败时，App 显示“校验失败”提示，而不是权限不足提示。
- 真机睡眠唤醒验收未执行前，任务保持“实现完成、待真机验证”，不宣称根因已现场消除。

## 5. 风险与回滚

- SMU 可能在延迟验证之后再次异步改表：本轮只提供立即 + 50 ms 两次校验，不做永久周期性重写；若真机日志仍显示漂移，再评估持续监测。
- work loop 与用户态主动写 P-state 仍沿用现有并发模型；不在本次引入新锁。复核确认仍存在两个窗口：用户写入无锁清除 work loop 的恢复/复核标志；唤醒重试期间再次睡眠时 `sleepState.pstate` 的快照 memcpy 与在执行的校验可能读到撕裂值（窗口约 50 ms，后果为多一次重试）。若真机日志出现异常重试，再评估用 work loop `runAction` 串行化。
- 恢复延后最多一个唤醒 tick，重试间隔 50 ms，避免在 PM 回调中增加等待。
- 回滚时恢复 0.7.6 kext/App；MSR 表为易失状态，冷启动可清除测试期修改。
